\section{Review of Previous Studies}

\subsection{Overview of Privacy-Preserving Mechanisms in Federated Learning}

\subsubsection*{Overall Landscape and Scope of Research}
The integration of Federated Learning (FL) into Intrusion Detection Systems (IDS) for IoT environments has resolved the issue of raw data centralization, yet the model weight sharing process itself still harbors data leakage risks~\cite{vyas2024}. To counter this, current studies classify Privacy-Preserving Federated Learning (PPFL) techniques into five main categories: Differential Privacy (DP), Homomorphic Encryption (HE), Secure Multi-Party Computation (SMPC), Trusted Execution Environments (TEE), and Blockchain~\cite{vyas2024}. Although TEEs provide a secure execution environment and Blockchain ensures transparency, they require specialized hardware or complex consensus mechanisms, which are unsuitable for the constrained resources of edge/IoT devices~\cite{manzano2025}. Therefore, this study implements DP and SMPC-based secure aggregation (SecAgg$^+$); HE is reviewed as an alternative but not implemented, because of its computational cost on constrained devices~\cite{nakayiza2026}.

\subsubsection*{Trusted Execution Environment (TEE)}
The Trusted Execution Environment (TEE) provides a completely isolated and secure hardware computing area for processing sensitive data, effectively preserving privacy. However, this technology is heavily dependent on specialized hardware security mechanisms and verifiable components. This strict hardware requirement makes TEE cumbersome and unsuitable for deployment across lightweight IoT networks comprising massively resource-constrained devices~\cite{vyas2024}.

\subsubsection*{Blockchain}
Blockchain preserves data privacy through decentralized ledgers and cryptographic algorithms that ensure tamper-resistance and eliminate the need for intermediaries. However, this system suffers from fatal performance weaknesses due to low throughput, high latency, and expensive verification costs stemming from continuously growing immutable storage. These severe latency and massive storage overheads make blockchain highly impractical for lightweight, multi-device IoT environments that demand rapid response times~\cite{vyas2024}.

\subsubsection*{Homomorphic Encryption (HE)}
HE enables computations to be performed directly on encrypted data, ensuring absolute security for model updates from clients before server aggregation without the need for decryption~\cite{nakayiza2026}. However, the computational cost and communication requirements of HE algorithms are extremely immense and heavy, leading to a surge in system latency~\cite{nakayiza2026}. This renders HE less feasible for systems requiring real-time responses and operating under resource constraints, such as IoT-based IDS~\cite{nakayiza2026}.

\subsubsection*{Differential Privacy (DP)}
Unlike the cumbersomeness of HE, Differential Privacy (DP) offers excellent scalability. The core principle of DP is to mask the contribution of any single data point by adding random noise to the model update at each client~\cite{ruzafa2022}. DP is exceptionally lightweight, consumes no extra bandwidth, and easily scales to tens of thousands of participating clients~\cite{ruzafa2022}. The tradeoff of this method is that injecting noise into the model inevitably degrades data accuracy, forcing engineers to constantly seek an optimal balance for the privacy budget~\cite{ruzafa2022}.

\subsubsection*{Secure Multi-Party Computation (SMPC/SecAgg)}
Conversely, Secure Aggregation (SecAgg) protocols based on SMPC comprehensively resolve the weakness of DP. SMPC prevents the server from directly observing individual client updates by ensuring that the server only receives the aggregated model update~\cite{bessaa2026}. Secure aggregation adds no statistical noise; with the fixed-point quantisation used by SecAgg$^+$, the aggregate differs from the plain sum only by a bounded quantisation error~\cite{bell2020}. As a trade-off, the original Secure Aggregation protocol requires multiple rounds of complex interactions between clients to exchange secret shares, causing severe bandwidth bottlenecks as the client population grows~\cite{bonawitz2017}; however, the subsequent SecAgg$^+$ protocol successfully resolves these overhead issues by replacing the complete communication graph with a $k$-regular graph, thereby reducing the per-client communication and computation complexity to a polylogarithmic scale~\cite{bell2020}.

\subsubsection*{Hybrid Privacy-Preserving Systems}
The study by Gutti et~al.~\cite{gutti2024} (integrating DP and SecAgg via the HADA algorithm) demonstrates that combining DP (to prevent inference attacks) and SecAgg (to protect the transmission channel) is a promising trajectory. However, stacking these security layers generates immense complexity in computation and hyperparameter tuning~\cite{gutti2024}. Therefore, before advancing to hybrid architectures, independently measuring the performance trade-offs between the DP pipeline and the SecAgg pipeline serves as a mandatory stepping stone to evaluate the endurance of the network system.

\subsubsection*{Distributed Differential Privacy}
Distributed DP combines the two families: each client adds only a share of the noise, and secure aggregation reveals only the sum, which carries the full calibrated noise~\cite{kairouz2021, agarwal2021}. Because secure aggregation operates on integers modulo a large number, discrete noise is preferred; the sum of independent Skellam variables is again Skellam, which permits exact privacy accounting after modular aggregation~\cite{agarwal2021}. The guarantee assumes that enough clients add their share honestly; with fewer honest clients the effective noise is smaller. Distributed DP fits releases that are a single sum, such as count tables, but not multi-step local DP-SGD, where each client's noise passes through non-linear local training before aggregation.

\subsection{Data Generation}

\subsubsection*{Overview of Data Generation Techniques}
In the field of cybersecurity and Intrusion Detection Systems (IDS) for Internet of Things (IoT) environments, Generative AI (GenAI) techniques for data generation are defined as deep generative paradigms capable of learning the underlying multivariate probability distribution of network traffic, thereby automatically synthesizing novel data samples whose structural attributes and statistical properties closely match genuine traffic distributions~\cite{deng2025}.

\noindent\textbf{Core problems addressed by data generation techniques:}
\begin{itemize}
    \item \textbf{Overcoming Extreme Class Imbalance:} Real-world IoT network traffic inherently exhibits extreme class skewness, where over 90--99\% of collected traffic consists of benign activity, while malicious behaviors---especially Low-Rate Stealth Attacks (LRSA) or rare DoS/DDoS variants---represent a negligible fraction. This acute shortage of attack samples severely biases downstream IDS classifiers toward majority classes, resulting in unacceptable false-negative rates on critical threats~\cite{deng2025}.
    \item \textbf{Beyond Interpolation-Based Oversampling:} Traditional statistical oversampling algorithms such as SMOTE~\cite{chawla2002} operate by performing linear interpolation between existing minority instances within a localized convex hull. As highlighted by Deng et~al.~\cite{deng2025}, deep generative models surpass these rigid boundaries by capturing the global multivariate distribution, enabling the synthesis of samples in unexplored regions of the feature space to cover edge cases and zero-day attack variants, thereby strengthening model robustness. Furthermore, because SMOTE requires simultaneous access to neighboring minority instances in a unified feature space, it is fundamentally ill-suited for federated environments where an individual edge gateway may hold few or no records of a rare attack class~\cite{chawla2002}.
    \item \textbf{Supporting Data Augmentation and Restructuring:} Systematic survey statistics indicate that up to 89\% of studies leverage GenAI specifically for data augmentation and class rebalancing, substantially improving the detection performance and generalization of IDS without exposing sensitive raw telemetry~\cite{deng2025}.
\end{itemize}

\noindent\textbf{Primary taxonomies of generative architectures in IDS:}
\begin{itemize}
    \item \textbf{Generative Adversarial Networks (GANs):} Architectures structured around an adversarial minimax game between a Generator network that creates synthetic samples from latent noise and a Discriminator network that evaluates sample authenticity. Due to their capacity to model sharp, high-dimensional distributions, GANs account for an overwhelming 58\% of research in generative IoT-IDS~\cite{deng2025}.
    \item \textbf{Autoencoders and Variational Autoencoders (AEs/VAEs):} Frameworks comprising an Encoder that maps high-dimensional traffic into a low-dimensional latent manifold and a Decoder that reconstructs the input. VAEs enforce continuous probability distribution priors over the latent space, permitting stable random sampling to synthesize realistic minority samples~\cite{deng2025}.
    \item \textbf{Transformer-Based Generative Models:} Architectures leveraging multi-head self-attention mechanisms to capture complex contextual correlations and sequential packet dependencies across temporal network traffic flows~\cite{deng2025}.
\end{itemize}

\subsubsection*{Analysis of Strengths and Weaknesses of Techniques in Existing Studies}
Although data generation techniques provide substantial potential for IoT-IDS, critical examination of existing literature reveals distinct computational bottlenecks, training instabilities, and privacy trade-offs when deployed in decentralized Federated Learning (FL) settings~\cite{deng2025}:
\begin{itemize}
    \item \textbf{Heavy Generative Denoising Techniques (Tabular Diffusion / Tab-DDPM):} Manzano et~al.~\cite{manzano2025} integrated tabular diffusion models (Tab-DDPM) directly at local FL clients to synthesize minority samples on the BoT-IoT benchmark. While Tab-DDPM achieves exceptional sample fidelity and distribution alignment, the reverse diffusion process requires iterative denoising over hundreds of sequential steps. On edge-tier testbeds (1 CPU core, 2\,GB RAM), generating a single synthetic sample requires approximately 32 seconds~\cite{manzano2025}. Such extreme computational latency is completely unviable for line-rate packet inspection in edge IoT environments.
    \item \textbf{Improved Policy-Guided GANs:} Yang et~al.~\cite{yang2025} employed an improved GAN guided by reinforcement learning to augment training sets for DDoS detection. While ablation experiments confirm that removing synthetic augmentation causes a noticeable drop in detection performance, the multi-component architecture requires up to 2.726 seconds per batch and consumes 19.6\,GB of GPU memory on the KDDcup99 dataset~\cite{yang2025}. Furthermore, the study did not isolate standalone generator inference latency, obscuring the true computational efficiency of the generator on edge hardware.
    \item \textbf{Survey Insights on Pure GAN Instability:} In their survey, Deng et~al.~\cite{deng2025} highlight that while GANs produce high-fidelity samples, the adversarial training dynamics are notoriously brittle and susceptible to mode collapse---wherein the generator repeatedly outputs a narrow set of duplicate patterns, wasting node compute without contributing meaningful diversity.
    \item \textbf{Random Resampling Techniques (Bootstrapping / Oversampling):} Jacob and Sultana~\cite{jacob2026} utilized bootstrapping (random resampling with replacement) at local nodes to balance the BoT-IoT and CSE-CIC-IDS2018 datasets. While computationally trivial and easily executable on microcontrollers, bootstrapping merely duplicates existing data points without expanding feature diversity. This encourages classifier overfitting and fails to generalize against evolving attack variants or concept drift~\cite{deng2025, jacob2026}.
    \item \textbf{Cloud-Based Centralized Data Generation Techniques (Cloud-Based VAE-GAN):} Anandhi and Srikanth~\cite{anandhi2026} proposed the SSAIM framework utilizing a hybrid VAE-GAN at the cloud coordinator to generate 51,200 Low-Rate Stealth Attack (LRSA) samples for the IoTID20 dataset, raising attack recall from 62\% to 98\%. However, placing data synthesis in the cloud violates the decentralized privacy principle of FL. Additionally, compressing the heavy VAE-GAN model via fixed-point quantization for transmission back to edge devices demonstrated that quantization below 6-bit (e.g., 4-bit) caused a severe degradation in detection sensitivity~\cite{anandhi2026}.
    \item \textbf{Federated Lightweight Edge GANs (TinyGAN in FL):} Durga et~al.~\cite{durga2026} deployed TinyGAN within a federated framework for IoMT malware detection, reporting 99.30\% accuracy after 20 rounds. However, to stabilize GAN training, all malware classes representing less than 0.5\% of the dataset were discarded, thereby sidestepping the core challenge of extreme class imbalance. Moreover, the study omitted standalone sample generation throughput measurements, leaving its actual computational advantage on constrained edge hardware unproven~\cite{durga2026}.
\end{itemize}

\subsection{Privacy-Preserving Generative Defenses and Research Gap}

\subsubsection*{Privacy-Utility Dilemma in Federated Generative IDS}
Federated intrusion detection systems (IDS) on edge networks must protect client telemetry while coping with severe minority-attack-class imbalance and non-IID traffic distributions. Differential privacy (DP) and cryptographic protocols bound gradient inversion and membership inference risks~\cite{cunhaneto2023} but do not correct class skew. Augmenting under-represented attack classes with federated generative models mitigates this imbalance, yet generative architectures may memorize training records and expose sensitive network traces through parameter exchanges or synthesized flows~\cite{cunhaneto2023}. Edge defenses must therefore limit the utility loss of synthetic data while providing formal client-side privacy guarantees.

Existing privacy-preserving generative IDS frameworks use cryptographic primitives, DP, or both. Cryptographic mechanisms, such as secure multi-party computation (MPC) and threshold secret sharing, preserve numerical precision without perturbation error~\cite{cunhaneto2023}. However, secure aggregation of high-dimensional neural parameters requires iterative multi-round communication, which burdens resource-constrained IoT edge devices~\cite{cunhaneto2023}.

\subsubsection*{Empirical Generative PPFL-IDS and Cryptographic Limitations}
A literature search of IEEE Xplore and SpringerLink (2022--2026) for studies combining federated learning, intrusion detection, and generative models (GAN or VAE) identified five empirical implementations, all from IEEE~\cite{yao2024, he2023, salim2025, jiao2025, shettar2026}. None applies cryptographic secure aggregation to uplink generator updates. Salim et~al.~\cite{salim2025} (global VAE aggregation), Jiao et~al.~\cite{jiao2025} (local CGAN gradients), and Shettar et~al.~\cite{shettar2026} (central aggregator with moments-accountant clipping at $\varepsilon = 4.8$ and $\delta = 10^{-5}$) rely on DP alone. He et~al.~\cite{he2023} combine local gradient noise with blockchain Proof-of-Authority consensus across edge servers, which ensures aggregation integrity and auditability rather than parameter confidentiality.

Yao et~al.~\cite{yao2024} use a hybrid design: proactive dynamic $(t, n)$-threshold secret sharing with $t=4$ and $n=5$ protects only downlink synthetic broadcasts, whereas uplink client gradients rely on Gaussian DP. They report execution measurements for key distribution and sample reconstruction (Table~VI), but secret sharing covers downlink tabular samples, not full model-parameter aggregation. Outside the primary search, Hamouda et~al.~\cite{hamouda2024} likewise omit secure aggregation and identify cryptographic model protection as an open challenge. Because none of these works benchmarks cryptographic aggregation against DP on model weights, their use of DP reflects a design choice rather than a measured trade-off.

The effect of DP perturbation on downstream detection depends on the privacy budget $\varepsilon$, gradient clipping threshold $C$, and minority-class sample density, yet existing studies do not isolate these factors. Utility can remain high at a moderate budget or with large synthetic volumes: Shettar et~al.~\cite{shettar2026} report a 96.8\% detection F1-score under central DP ($\varepsilon = 4.8$), and Hamouda et~al.~\cite{hamouda2024} observe a 0.25-percentage-point accuracy reduction at $\varepsilon = 1.0$ when applying DP-SGD to the downstream global classifier with 50,000 synthetic samples per class. Generative augmentation can also raise rare-class detection from sparse baselines: He et~al.~\cite{he2023} report that CGAN augmentation improved Infiltration F1-score from 33.33\% to as high as 98.01\%, starting from 29 baseline training samples. However, Hamouda et~al.~\cite{hamouda2024} applied DP to the classifier rather than the generator, and neither He et~al.~\cite{he2023} nor Jiao et~al.~\cite{jiao2025} report formal numerical $(\varepsilon, \delta)$ budgets. Because generator-side DP must spread privacy noise across iterative training steps, how strict bounds ($\varepsilon \le 1.0$) interact with extreme class scarcity in federated generative architectures remains an open empirical question.

\subsubsection*{Marginal-Based Tabular Synthesis vs. Deep Generative Models}
Marginal-based tabular synthesis offers an alternative to deep generative models. Instead of optimizing non-convex neural network weights by backpropagation, marginal synthesizers select and measure low-order contingency tables and reconstruct the data distribution with probabilistic graphical models. Beyond network IDS research, a cross-domain search of the ACM Digital Library, PMLR, and arXiv identified distributed extensions: Maddock et~al.~\cite{maddock2024} introduce FLAIM, which adapts the Adaptive and Iterative Mechanism (AIM) to distributed clients under zero-concentrated differential privacy ($\rho$-zCDP) and compares DP with secure multi-party computation (DistAIM); Pentyala et~al.~\cite{pentyala2024} present CaPS, a ``DP-in-MPC'' framework in which secret sharing protects marginal selection and measurement; and Li et~al.~\cite{li2026} propose HeteroFedSyn, which compresses two-way marginal dependencies by random projection under distributed perturbation.

Marginal synthesizers avoid the adversarial minimax training instability of GANs but carry their own privacy-utility trade-offs. Iterative selection-and-measurement algorithms (e.g., AIM and Private-PGM) divide the total privacy budget $\varepsilon$ across rounds, and distributing measurements across federated clients compounds perturbation noise~\cite{maddock2024, pentyala2024}. In sparse discrete categories with small contingency cell counts, additive Laplace or Gaussian noise yields a low signal-to-noise ratio. Restricting measurements to low-order marginals (typically two-way dependencies~\cite{li2026}) truncates higher-order multivariate correlations, and continuous flow variables require discretization, which introduces binning artifacts.

Federated marginal generators have so far been evaluated mainly on general-purpose tabular benchmarks from demographic, financial, and biomedical domains (e.g., Adult, Census, Credit Card Fraud, COMPAS, Diabetes)~\cite{maddock2024, pentyala2024, li2026}. FLAIM~\cite{maddock2024} also used the legacy DARPA Intrusion Detection benchmark but evaluated only workload error and negative log-likelihood, not downstream minority-class intrusion classification. Decentralized tabular GANs with cryptographic primitives also exist: Duan et~al.~\cite{duan2023} combine Paillier additively homomorphic encryption for global multimodal distribution encoding with DP during GAN training, but evaluate statistical utility and membership inference resistance on legacy tabular data (KDD Cup 99), not modern protocol telemetry.

\subsubsection*{IoT-MQTT Protocol Telemetry and Working Hypotheses}
IoT-MQTT telemetry combines structured, low-cardinality discrete protocol fields (e.g., message types, QoS levels, retain flags) with continuous flow metrics (e.g., payload lengths, burst durations). Sparse discrete feature combinations form low-count contingency cells, where both generative families risk degradation under DP noise, making this a suitable setting for examining these trade-offs. We hypothesize that, under generator-side DP at strict budgets ($\varepsilon \le 1.0$), a federated marginal synthesizer achieves higher minority-class detection F1-score than a federated deep generative model for attack classes defined by low-order (two-way) discrete header correlations (e.g., MQTT Unauthorized Connect, Malformed Header). We expect the reverse for volumetric or timing-based attacks (e.g., MQTT Publish Floods) governed by multi-attribute continuous flow dynamics. We test this across five random seeds, equalizing privacy budgets by converting all mechanisms to $(\varepsilon, \delta)$-DP under R{\'e}nyi differential privacy accounting, and compare class-specific F1-scores with a Wilcoxon signed-rank test (treating a margin $|\Delta\mathrm{F1}| \ge 2.0$ percentage points at $p < 0.05$ as statistically significant).

\subsubsection*{Identified Research Gaps}
To the best of our knowledge, the IEEE, Springer, ACM, PMLR, and arXiv searches described above indicate three distinct research gaps:
\begin{itemize}
    \item \textbf{Marginal Synthesis for Protocol Telemetry:} Deep generative models have been evaluated on MQTT-bearing datasets (e.g., Hamouda et~al.~\cite{hamouda2024}, federated conditional GAN on Edge-IIoTset), but no prior study evaluates a federated marginal-based generator on modern IoT-MQTT telemetry or examines how mixed discrete-continuous features affect marginal synthesis relative to deep models.
    \item \textbf{Controlled Architectural Comparison:} No empirical study compares a federated marginal-based synthesizer with a federated deep generative model (e.g., CGAN, VAE) under identical non-IID client partitions, minority-attack imbalance ratios, and calibrated generator-side privacy budgets $(\varepsilon, \delta)$.
    \item \textbf{Downstream Detection Trade-offs:} Prior marginal studies compared DP with cryptographic aggregation on workload error, negative log-likelihood, runtime, and communication bandwidth~\cite{maddock2024, pentyala2024}, and decentralized GANs were evaluated for statistical utility and membership inference resistance~\cite{duan2023}. No study quantifies how choosing between DP and cryptographic secure aggregation affects downstream minority-class intrusion detection under matched federated edge conditions.
\end{itemize}

This study addresses these gaps by evaluating communication overhead, synthetic sample fidelity, and downstream minority-class intrusion detection for marginal and deep generative models under both DP and cryptographic secure aggregation on edge IoT networks.

\section{Summary of the Literature Review}\label{sec:lit_summary}
The reviewed literature establishes federated learning as a promising approach to IoT intrusion detection while identifying persistent limitations in data representation, privacy protection, and empirical evaluation. As summarised in Table~\ref{tab:lit_review_comparison}, several studies address non-IID data distributions or incorporate data augmentation, but these features alone do not demonstrate effective detection of under-represented attack classes. Class imbalance and inter-client heterogeneity therefore remain central concerns. Two generator families address them under privacy constraints, deep generative models trained with DP-SGD and marginal-based synthesis, but they have been evaluated separately and rarely on IoT traffic; whether either adds detection value must be verified through controlled experiments.

The comparative synthesis in Table~\ref{tab:lit_review_comparison} shows that privacy preservation and synthetic data generation have increasingly converged across distributed and federated environments. On the one hand, several intrusion detection frameworks employ deep generative models, such as generative adversarial networks and variational autoencoders, to address severe class imbalance and zero-day threat variants in IoT, UAV, and satellite networks (e.g.,~\cite{hamouda2024, yao2024, he2023, salim2025, jiao2025, shettar2026}). On the other hand, recent advances in tabular data synthesis, including FLAIM~\cite{maddock2024}, CaPS~\cite{pentyala2024}, and HeteroFedSyn~\cite{li2026}, have extended marginal-based synthesis to distributed or federated settings using differential privacy (DP) and secure multi-party computation (SMPC). However, these marginal-based synthesisers have been validated almost exclusively on general-purpose tabular benchmarks (such as Adult, Census, and Credit Card Fraud) rather than on streaming network telemetry, leaving their efficacy in packet-level IoT intrusion detection unexamined.

More critically, an inspection of Table~\ref{tab:lit_review_comparison} highlights two persistent research gaps in the literature:
\begin{itemize}
    \item \textbf{Absence of a controlled DP versus SecAgg trade-off analysis:} Cryptographic protection (SMPC and SecAgg/SecAgg$^+$) preserves exact parameter sums without statistical noise but incurs communication and round complexity. Conversely, perturbation-based protection (DP) offers formal mathematical bounds against inference attacks at the expense of utility degradation. While several hybrid systems incorporate aspects of both paradigms (e.g.,~\cite{gutti2024, yao2024, maddock2024}), none provides an explicit, head-to-head empirical trade-off analysis comparing a purely cryptographic pipeline against a perturbation-based pipeline under identical IoT network conditions, non-IID partitions, and threat models.
    \item \textbf{Untapped distributed DP for federated marginal synthesis in IoT:} Although discrete distributed DP mechanisms, such as discrete Gaussian~\cite{kairouz2021} and Skellam~\cite{agarwal2021} noise, permit noise shares to be split across clients and reconstructed exactly over modular secure aggregation, existing federated intrusion detection architectures continue to rely on centralised DP noise injection or local DP-SGD. Furthermore, deep generative approaches and marginal-based mechanisms have developed in isolation, without a unified benchmark to determine whether lightweight count-table synthesis retains sufficient utility compared with complex deep generative baselines.
\end{itemize}

To the best of our knowledge, based on a non-systematic search of the literature, no prior study has jointly addressed these limitations within a unified federated framework. This observation motivates PP-FedData, which addresses the gap by implementing: (i) a federated marginal-based generator (FedDP-Marginal) tailored to IoT-MQTT network traffic; (ii) an end-to-end distributed differential privacy mechanism using integer Skellam noise aggregated through Flower's SecAgg$^+$ protocol, alongside a federated CVAE deep generative baseline; and (iii) a controlled evaluation across five dimensions: downstream IDS utility, synthetic-data fidelity, formal privacy accounting, operational overhead, and statistical rigour.

\section{Contribution of Research}\label{sec:contribution}
To address the limitations and research gaps identified in Section~\ref{sec:lit_summary} and synthesised in Table~\ref{tab:lit_review_comparison}, namely the lack of marginal-based private synthesis for IoT telemetry, the absence of distributed differential privacy for tabular count data, and the lack of an explicit empirical DP-versus-SecAgg trade-off benchmark, this research proposes PP-FedData and makes three primary contributions.

\subsubsection*{G1. A Federated Marginal-Based Generator for Non-IID IoT-MQTT Traffic (FedDP-Marginal), with a Deep Generative Baseline}
Table~\ref{tab:lit_review_comparison} shows that existing marginal-based synthesisers (e.g., FLAIM~\cite{maddock2024}, CaPS~\cite{pentyala2024}, HeteroFedSyn~\cite{li2026}) have only been evaluated on generic tabular datasets. This study develops FedDP-Marginal, tailored to packet-level IoT-MQTT network traffic. Across three communication rounds, the framework releases noisy per-class 1-way marginal tables, global 2-way tables from which a single Chow--Liu dependency tree is learned~\cite{chow1968}, and class-conditional tables along that tree; synthetic packets are then sampled class by class. It adapts central differential privacy synthesis mechanisms (MST~\cite{mckenna2021mst}, PrivBayes~\cite{zhang2017privbayes}) to a federation of distributed gateways and adds post-processing heuristics (fusion of independent marginal estimates and iterative proportional fitting) that consume no additional privacy budget. A federated conditional variational autoencoder (CVAE)~\cite{sohn2015cvae} trained with FedAvg~\cite{mcmahan2017} serves as the deep generative baseline under identical data partitions, downstream classifiers, and evaluation criteria, which establishes whether structural marginal modelling offers operational advantages over deep generative alternatives.

\subsubsection*{G2. Distributed Differential Privacy through a Real Secure Aggregation Implementation, with Explicit Trust Assumptions}
In contrast to the federated intrusion detection architectures in Table~\ref{tab:lit_review_comparison}, which inject heuristic local perturbation without cryptographic aggregation or rely solely on centralised server-side noise, PP-FedData integrates formal distributed DP with a real cryptographic protocol. For FedDP-Marginal, integer Skellam noise~\cite{agarwal2021} is split across the edge gateways, and the noisy tables are summed with Flower's SecAgg$^+$ protocol~\cite{bell2020}, so that the honest-but-curious aggregator observes only the noisy sum. The cumulative privacy budget $\varepsilon$ is accounted for with the Rényi differential privacy (RDP)~\cite{mironov2017rdp} bound established by Agarwal et~al.~\cite{agarwal2021} and is reported explicitly as a function of the number of honest gateways. The framework is configurable in two respects: (i) a threshold $t$ of required honest gateways, and (ii) the protection unit, which is record-level (one packet) by default and optionally stream-level or capture-level when each unit is held by a single gateway and capped at $m$ rows. A local-DP variant is provided for clients that trust no other party. For the deep CVAE baseline, differentially private stochastic gradient descent (DP-SGD)~\cite{abadi2016dpsgd} with per-example gradient clipping and Rényi accounting is combined with fixed-point quantised SecAgg$^+$.

\subsubsection*{G3. A Controlled Five-Dimensional Empirical Evaluation and a Requirement-Driven Configuration Guide}
To resolve the fragmentation observed in prior studies, all configurations (FedDP-Marginal, the CVAE baseline, and non-private variants) are evaluated against the same held-out test split of real IoT-MQTT traffic along five dimensions:
\begin{itemize}
    \item \textbf{Downstream IDS utility:} macro-F1, binary F1, per-class precision and recall, and minority-attack recall, for IDSs trained on purely synthetic data (TSTR), on real data augmented with synthetic data (TAug), and with per-gateway local augmentation.
    \item \textbf{Fidelity:} Wasserstein distance, Jensen--Shannon divergence, correlation distance, and classifier two-sample tests (C2ST), which assess the preservation of multi-attribute dependencies.
    \item \textbf{Privacy:} formal $(\varepsilon, \delta)$ budgets recomputed independently with the privacy accountants, together with empirical membership inference attacks (MIA) that use positive controls.
    \item \textbf{Operational overhead:} upstream and downstream communication volume (bytes per round), number of rounds to convergence, end-to-end training and sampling time, and peak memory usage.
    \item \textbf{Statistical rigour:} three random seeds, paired bootstrap confidence intervals, a fixed decision rule, and stream-level bootstrap sensitivity checks.
\end{itemize}
Finally, building on these empirical findings, the research derives a transparent decision rule that filters valid configurations by operational requirements (server trust, gateway collusion risk, bandwidth limits, and target attack priority) and selects the most suitable operating point from their empirical Pareto front.
